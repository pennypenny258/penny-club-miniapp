## 已完成的产品能力（匿名演示）

### 会员端

- 动态页使用统一公开搜索，并明确只搜索会员授权公开信息。
- 第二个 Tab 已改为“活动”，展示线上/线下、等待开启/已完成、时间、地点、分享者/参会者，以及受控会议或回放入口。
- Agents 已收敛为一个需求窗口：我是谁、背景、具体需求；支持公开或私密匹配，语音入口明确标记为待配置。
- “我的”展示会籍、续费方案、公开名册、在职核验、需求通知和收藏；支付不会伪造成功。
- 公开名册与内部 CRM、付款证据、会籍判定相互隔离；联系方式始终走申请和运营代转。

### 运营后台与服务端

- 会员 CRM、四类会籍档位、群状态硬门禁、续费候选和人工复核规则已建模。
- Excel/CSV 脱敏预检、冲突演练、付款线索和公开名册独立审核流程可用，但不会写入生产库。
- Agent 支持投资、融资、并购、招聘、招商；具备人工审核、三种分发方式、3-of-4 定向候选、14 天去重、三段式申请和运营代转边界。
- 正式微信身份、后台会话、CloudBase 网关、私有对象存储和 Agent RPC 均有失败关闭的代码边界；默认全部禁用。
- 生产镜像默认进入 `cloudbase_production_bootstrap`，只允许健康检查，会员端、后台和业务 API 不会误回退到演示数据。

## 云端与域名现状

以下结论只来自公开网络探测和项目记录，未把“代码准备完成”误写成“云端已经上线”：

- 项目记录显示 CloudBase PG 的 001—008 是当前基线；009 管理员治理明确延期，不应继续重试。
- `test-api.pennysclub.com` 当前公共 DNS 无解析记录，因此自定义测试域名尚未接通。
- CloudBase 默认测试域名能够解析 IP，但 12 秒内未返回 `/healthz`；结合此前控制台显示，测试服务需要在 CloudBase 中确认是否仍暂停、部署是否成功以及流量是否已切到新版本。
- 小程序当前仍指向 CloudBase 默认测试域名，且关闭合法域名校验，只适合开发者工具联调。
- 正式发布检查仍按设计失败：服务器域名校验关闭、development/演示模式、存在 HTTP 本机地址、仍含仅测试的 CloudBase 默认域名配置。

## 下一阶段优先级

### P0：先恢复一个稳定的匿名测试环境

1. 在 CloudBase 确认 `penny-club-test-api` 使用 GitHub `main`、Dockerfile、端口 3000 和 staging 五项环境变量。
2. 恢复测试服务并验证默认域名的 `/healthz`、`/member/`、`/admin/`。
3. 完成 `test-api.pennysclub.com` 的域名归属 TXT、免费 HTTPS 证书、CNAME/HTTP 路由和全路径透传。
4. 自定义域名稳定后，把小程序 staging 地址改为 `https://test-api.pennysclub.com`，重新做开发者工具和真机匿名验收。
5. `penny-club-prod-api` 继续保持 production bootstrap 锁定态；不要把 staging 环境变量或匿名数据放入正式服务。

### P1：完成真实 MVP 的最小闭环

1. 以已确认的 001—008 为基线，离线完成并审查不依赖 009 的 CRM、会员绑定和 Agent 最小前向包。
2. 接通正式后台身份与 008 会话/RBAC；演示请求头不得进入生产。
3. 接通微信 `code2Session`、用户主动手机号授权、CRM 唯一匹配、异常人工复核和每次请求重新计算会籍。
4. 接通 CloudBase 服务端网关的最小持久化读写、幂等、审计和失败关闭；先使用匿名 canary，不导入真实表。
5. 接通私有对象存储，用于在职名片等最小必要文件；对象键和长期链接不得返回客户端。
6. 完成公开名册和 Agent 的端到端生产验收：提交、审核、公开/私密匹配、申请、需求方同意、运营代转，全程不由 API 泄露联系方式。

### P2：发布与运营准备

1. 准备 `api.pennysclub.com`、有效 HTTPS 证书和微信小程序 `request` 合法域名。
2. 完成隐私政策、用户协议、授权版本、数据留存/删除期限和高敏信息处理台账。
3. 建立数据库备份恢复、结构化脱敏日志、监控告警、审计抽查和最小权限复核。
4. 用脱敏副本演练 CRM 导入，再用极小批真实数据做受控 canary；通过后才扩大批次。
5. 清除所有 release check 阻断项，完成开发者工具、体验版和真机验收后再提交审核。
