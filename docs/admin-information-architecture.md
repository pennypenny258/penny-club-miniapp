# 运营后台信息架构

运营后台采用“一级业务模块 + 页内二级视图 + 全局待办”的结构。一级导航固定为六项，不再把每个审核队列平铺为全局 Tab。

| 一级模块 | 页内二级视图 |
|---|---|
| 工作台 | 总览、全局待办、风险 / 提醒 |
| 会员 | 最终会籍、判定记录、内部 CRM、公开名册、资料更新审核、在职核验、续费方案、历史订单 |
| 资料与导入 | 从电脑导入资料（首选）、知识库、飞书迁入（可选）、CSV 迁移清单、自愿名册导入、付款证据导入、付款证据、导入批次、异常修正 |
| 活动 | 活动列表、报名状态、通知任务、回放归档 |
| 需求与撮合 | 人工终审、AI 初筛、申请 / Agent 分发、会员对接 |
| 设置与审计 | 审计日志、数据治理说明、运行 / 发布检查 |

## 全局待办

后台标题区下方始终显示跨模块待办，包括会籍复核、公开资料审核、在职核验、导入异常和通知重试。工作台的“全局待办”页进一步汇总需求终审与申请分发，点击卡片进入对应模块处理。

## 隔离与权限

本次重构只改变后台导航和页面组合，不改变数据域与服务端规则：

- CRM、公开名册、付款证据、会籍判定仍为独立域。
- 导入预检、异常修正、人工审核和发布流程保留原 API 与审计。
- 在职材料仍只显示安全元数据，会员端不返回 CRM、付款或内部材料。
- 活动报名与会议链接门禁、需求匿名化和分级披露规则保持不变。
- 移动端一级模块和二级视图均采用横向滚动，避免队列挤压或多行堆叠。

后台上线收口后增加系统管理员、运营人员、审核人员、审计人员四角色。权限由服务端逐请求校验，列表提供搜索/状态筛选；高风险最终动作要求再次确认和幂等键。六个一级模块保持不变，新增能力均落在原有二级视图、全局待办或“运行 / 发布检查”中。完整说明见 `admin-launch-readiness.md`。
