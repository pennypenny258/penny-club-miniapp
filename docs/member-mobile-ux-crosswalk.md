# 会员端移动体验需求对照

## 目标与范围

本轮只重构会员端移动体验，浏览器预览和原生微信小程序统一为四个固定底部入口：动态、资料库、Agents、我的。运营后台继续采用既有六模块信息架构。本文件以既有 PRD、安全规则与本轮移动原型的并集作为验收依据。

## 状态说明

- 已实现：四个移动入口、安全聚合与搜索、五个资料分栏、下载开关、匿名五类机会、文本匹配请求、对接通知、收藏、本人会籍和续费状态、公开资料待审核更新。
- 原型状态：浏览器演示身份、语音录音提示、续费支付提示、在职材料安全元数据提交。原型不会伪装已取得微信资料、已完成语音转写、AI 匹配或支付。
- 正式依赖：公司主体 AppID、微信登录、微信支付、订阅消息、录音授权与 ASR、生产数据库、私有对象存储、文件安全检查、隐私协议与授权留痕。

## 不得突破的安全规则

1. 会籍由微信身份绑定、有效期、群内状态与有效付款/人工复核综合判断；付款证据不能单独激活会籍。
2. 内部 CRM、付款证据、最终会籍、公开名册是独立数据域；会员端仅接收白名单字段。
3. 公开名册必须由会员明确同意并经人工审核；联系方式不公开，默认通过申请对接。
4. 手机号、微信、名片内容、CRM 备注、订单、付款证据、飞书来源、外部 ID、存储路径、会议链接和高敏感材料不得进入搜索、动态、演示数据或普通会员响应。
5. 私密机会只允许 Agent 在私有库和已授权公开资料间受控匹配；申请人看不到私密库或联系人。
6. AI 初筛后必须人工终审；联系人共享须被申请者明确同意并由运营受控履行，接口同意响应仍不返回联系方式。
7. 活动报名不承诺腾讯会议席位；会议链接仅在指定时间窗向会籍有效且已报名会员开放。
8. 公开资料编辑保存为独立更新记录，审核通过前不得改写已发布名册；在职材料只进入内部核验队列且不自动改变会籍或公开资料。

## 390px 视觉检查

- 验收视口：390 × 844；截图见 `docs/member-mobile-390.png`。
- 固定底栏宽度 390px、高度 62px，贴合视口底部；主内容独立滚动，不被底栏遮挡。
- 动态、资料库、Agents、我的四个入口均可切换；白底、`#F5F5F5` 分区、细分割线和系统字体保持微信原生基线，当前状态与主要操作使用克制的浅紫/中紫强调。
- 中紫强调文字及紫底白字主要按钮均达到至少 4.5:1 的对比度；正文黑灰与警告、收藏等语义色保持独立，没有全部紫色化。
- 五个资料分栏可横向滚动；下载关闭时没有按钮，开启时仍只能得到“私有存储待配置”的安全提示。
- 浏览器控制台无错误或警告；运营后台入口及原六模块导航未受影响。
