# 当前三项优先能力：匿名操作演练

本清单只用于本机匿名演示。不得选择真实文件，不得粘贴真实 CRM、订单、名册、联系方式或凭据；页面状态在内存或浏览器会话中，不能视为 CloudBase 持久化成功。

## 1. 会员 CRM 运营演练

从后台 **会员 → 会员 CRM 库（首选）** 开始。页面按“导入来源 → 会员 CRM → 自动匹配 → 人工补全 → 运营确认”组织，不再让运营者在一排技术队列之间切换。

1. 载入匿名微信群标签 OCR 样本。OCR 只提出标签、日期和匹配候选，必须人工确认。
2. 在首屏“付款线索”卡片点击 **导入付款记录**。微信小店整表只读取收件人姓名、订单发货时间、收件人手机号和商品价格，其他列自动忽略；可选填 A1/A2 价格规则。商户号可一次选择多个小票表，页面显示文件数量、各文件安全摘要和整批汇总；单个异常文件不会让其他合格文件消失。手动转账仍使用自己的四类最简字段。预检不显示文件名、姓名、手机号、价格、订单号或逐行原文。三者只用于匹配和补全 CRM，不能单独激活会籍。
3. 在“CRM 补全”点击 **导入 CRM Excel**；在页面底部独立公开名册区点击 **导入自愿名册 Excel**。付款、CRM 与名册均支持常规整表上传，安全硬上限统一为 10MB / 10,000 行；结果仍进入各自独立复核域。
4. 对未匹配、重复候选或日期冲突逐行处理；不能自动跳过。
5. 在成员详情中补群状态、标签日期、付款来源缺项和 CRM 状态。
6. 运营最终判断以是否仍在大群为硬门禁。已退群、已移除或未知不放行；标签日期已到期但仍在群且尚未通知续费时，显示“待续费跟进 / 仍暂时有效”，不自动失效。

CRM、付款证据、自愿公开名册、最终会籍判定在底层仍是四个独立事实域。公开名册位于会员模块的独立队列，CRM、付款或群标签不能自动生成公开资料。

## 2. 资料导入演练

从“资料与导入 → 从电脑导入资料”进入。只使用项目内匿名测试样本或先创建无文件条目，不得选择真实文件。

- 报告、书籍、回放和模板可批量上传。上传前在“批量应用到本批”统一设置分类、标签和下载开关，再按需要逐项覆盖；单项通过安全校验后直接发布，失败只标记该项，不影响其他合格文件。
- 名册或任何含会员身份、联系方式、同意状态的文件不得作为普通资料上传；公开资料由“会员 → 公开名册 / 公开名册审核”独立维护。
- 受控运营资料在上传时一次确认分类、版权和文件安全责任；校验成功后直接发布并进入会员动态。历史待处理资料、未知分类资料和失败项不会自动公开。
- 关闭下载只隐藏下载入口，不等于禁止受控查看。
- PDF、Office、图片和音视频在预览/转码未配置前只显示能力边界，不伪装可在线阅读，也不返回内部存储定位。

## 3. 需求撮合演练

从后台“需求与撮合 → 需求撮合演练（首选）”查看全链路，会员端使用“Agent”。

1. 会员提交不少于 20 字的匿名需求描述。
2. 当前只显示规则提示和“AI 待配置”，不得声称真实 AI 已读资料。
3. 运营仅基于匿名标题、摘要和类型进行人工终审。
4. 已通过的招聘、融资、并购、投资或招商机会才在会员端匿名展示。
5. 会员申请后，Agent 进行二次分发；会员可在“我的机会申请”查看状态。
6. 需求方最终选择受控介绍、拒绝或继续 Agent 分发。即使同意介绍，联系方式仍不由接口返回，须由未来的受控运营流程完成。

验收时确认会员响应中没有 CRM、付款、私密联系人、公司真实名、交易细节或内部对象定位。
