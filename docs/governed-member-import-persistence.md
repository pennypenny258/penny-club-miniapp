# CRM、付款、公开名册与会籍判定：持久化导入准备

当前状态：**只完成代码、SQL 和离线契约，真实流程仍关闭。** 匿名 CloudBase staging 不会接收 CSV，不会连接真实数据库，也不会回退到本机内存后宣称“已持久化”。现在不要执行 SQL、创建 Key 或配置密钥。

## 四个事实域始终独立

| 域 | 导入模板 | 可以产生什么 | 绝不能自动产生什么 |
| --- | --- | --- | --- |
| 内部 CRM 核验 | `templates/internal-crm-verification.csv` / 后台 XLSX 模板 | 历史续费信息、私有匹配与补全候选 | 公开名册、付款已验证、有效会籍 |
| 付款证据 | `templates/wechat-shop-order-evidence.csv` | 私有付款证据候选 | CRM 已核验、公开名册、单笔订单直接激活 |
| 自愿公开名册 | `templates/voluntary-directory-import.csv` | `consent=yes` 且人工 `approved` 后的无联系方式资料 | CRM/付款同步、联系方式、自动公开 |
| 最终会籍判定 | 不接受 CSV 直接导入 | 基于最小四域投影的可追溯人工判定 | CRM、订单、群状态、联系方式返回会员端 |

公开名册固定使用 `request_only` 申请对接。撤回同意后必须隐藏；CRM 与付款导入不会创建或修改公开名册。

## 未来服务端工作流

1. 真实后台会话先完成身份验证与 RBAC；浏览器上传的 `.xlsx` / CSV 只到 Node 服务端。
2. Node 允许常规整表并设置 10MB/10,000 行、64 列及解压后 64MB 的安全硬上限；安全读取 `.xlsx` 或 UTF-8 CSV，并验证重复/未知/危险表头、宏、外部链接、隐藏批注和公式注入；服务端不执行 Excel 公式。
3. 手机号、微信匹配信息、内部引用和备注只生成带密钥哈希及 AES-GCM 加密载荷；普通响应、复核队列和日志不回显原值。
4. 预检阶段不创建任何批次。运营明确确认后，固定 RPC 才创建私有批次；常规大表最多 10,000 行，服务端按每段最多 500 行传输并在全部到齐后一次完成。网关或数据库失败返回 503，不转存内存或本地文件。
5. 私有匹配令牌只形成候选；零候选、多候选、退款、群状态 unknown、字段冲突一律人工复核。
6. 复核决定使用幂等键并写追加式脱敏审计。后续 007 已准备“复核后分域物化”的离线契约，但真实业务路由仍未开放，详见 `docs/governed-materialization.md`。
7. CRM、付款、账户或群状态变化会立即写入一条 `needs_review` 判定并排队重算，旧判定不能继续放行。
8. 只有账号正常、会籍窗口当前、CRM verified、最近付款证据已人工复核且无退款、群状态 in_group、无冲突并再次人工批准，才可写入 active 最终判定；004 entitlement 仍只返回最小门禁布尔值。

## 未来 CloudBase 执行顺序（现在不要执行）

只有在以下条件全部满足后，才进入 CloudBase SQL 编辑器：已备份/确认测试库、真实后台身份方案完成、离线与集成测试通过、用户明确批准迁移窗口。

现有 CloudBase 只完成 001 / CloudBase 002 / 003 / 040。未来最小安全顺序是：

1. 004 → 140 → 190；
2. 005 → 250 → 260 → 290；
3. 006 → 340 → 390；
4. 007 → 440 → 490；
5. 008 → 540 → 590；009 → 640 → 690（正式后台会话与权限前置）；
6. 最后严格按 `server/db/cloudbase-pg-console/crm-master-import-manifest.json` 执行 011 → 740 → 790；
7. 任何一步报错立即停止，不继续执行，也不要临时修改 SQL 重试；只有 790 全部为 `true` 后，服务端迁移标识才可准备为 `011_crm_master_import`。

这条路径使用 CloudBase 官方 HTTPS 后端网关，不需要购买标准版私有网络。`service_role`、加密密钥和匹配 HMAC 密钥未来只配置在云托管服务端；不要放进浏览器、小程序、仓库、截图或聊天。

## 分阶段数据准入

- 第一轮只使用模板和脱敏假数据，核对行级错误、重复候选、回滚和审计。
- 第二轮使用专门构造的脱敏副本做人工匹配演练，仍不启用会员 entitlement。
- 真实后台身份、双人复核、撤销/退款重算、备份恢复和安全日志均验收后，才另行批准真实 `.xlsx` / CSV。
- 首次真实导入顺序建议：CRM 小批次 → 人工匹配 → 付款小批次 → 退款复核 → 自愿名册小批次 → 最终会籍重算。每个域独立验收，不能一键联动。

当前只在本地使用模板和匿名数据演练。请勿把真实 CRM 表放进当前演示服务，也不需要现在进入 CloudBase、创建 Key、Bucket 或环境变量。上线前逐项检查见 `docs/crm-persistence-launch-checklist.md`。
