# 低成本需求匹配实施边界

当前版本只提供离线、可测试的规则优先边界，不调用真实模型、不自动发布、不自动发送提醒，也不释放联系方式。

## 执行顺序

1. 用需求类型关键词、运营标签以及“人 / 机构 / 角色 / 事项”四项结构化条件做首轮筛选。
2. 三项以上明确匹配只生成“可供运营查看的定向候选”，仍需人工审核并手动发送。
3. 规则置信度低时，未来才允许服务端调用小模型做结构化和摘要；手机号、邮箱、微信号先脱敏，密钥只放服务端。
4. 同一脱敏输入使用哈希缓存；设置每日调用上限。嵌入采用公开安全摘要的批处理，禁止 CRM、付款、联系方式、订单和内部备注进入嵌入。
5. 模型或网关不可用时保留规则草稿并进入人工处理，不声称 AI 成功。

## 上线前必须补齐

- 选择服务端模型供应商，完成数据使用、存储地域和保留期审查。
- 配置独立的服务端密钥、调用预算、缓存和告警；前端与小程序不得获得密钥。
- 对规则、模型草稿和候选结果执行人工审核；模型不得自动公开、定向推送或改变联系人披露状态。
- 联系方式仍遵循“申请说明 → 需求方同意 → 运营代为转交”，禁止模型直接读取或输出。
