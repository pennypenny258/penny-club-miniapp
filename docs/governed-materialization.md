# 人工复核导入行 → 分域正式物化（离线准备）

当前只完成离线代码、007 前向迁移和匿名契约测试。**没有真实后台路由、没有连接 CloudBase、没有执行 SQL，也没有物化任何事实。** 现在不要创建 Key、配置变量、上传 CSV 或进入 SQL 编辑器。

## 职责分离状态机

1. 导入人创建私有批次。
2. 匹配复核人确认导入行与内部会员的关系；带行级错误、零候选或冲突的行不能进入物化。
3. 第二复核人检查解密后的受保护载荷并创建不可变物化请求。该人员不能是导入人或匹配复核人。
4. 独立执行人调用固定服务端 RPC，在单一数据库事务内写入一个事实域。该人员不能是前述三者。
5. CRM 或付款写入会触发会籍立即失效和重算队列。单笔订单仍不产生 active 会籍。
6. 自愿名册只先写成 `hidden / pending_publication`；第四位独立审批人再次确认 `consent=granted` 与 `contact_mode=request_only` 后才可见。
7. 事务内任一步失败全部回滚；提交后的业务错误只能走显式补偿。补偿不删除审计记录，会把 CRM/付款降为待复核或排除、隐藏名册，并把导入行退回人工复核。

## 三个物化域

| 域 | 正式事实 | 物化后的默认结果 | 与其他域的边界 |
| --- | --- | --- | --- |
| CRM | `crm_verifications` | 按复核状态保存；任何变化触发会籍重算 | 不创建付款或公开名册 |
| 付款证据 | `payment_evidence` | 无退款且产品规则 matched 才可为 verified；其他均 needs_review | 不验证 CRM、不激活会籍、不创建名册 |
| 自愿名册 | `public_directory_profiles` | 首先 hidden；独立审批后才 visible | 不读取订单/CRM 联系方式，固定申请对接 |

会员端仍只读取 004 的最小 entitlement，不会收到 CRM 状态、付款原值、退款细节、群状态、电话、微信、内部引用、审计或物化请求。

## 幂等、补偿与审计

- 同一个服务端幂等键只对应同一导入行和同一复核人；重复请求返回原请求，不重复写事实。
- 每行最多一个物化请求、每个请求最多一个正式事实和一个效果记录。
- 网关失败统一为 503，不能回退内存或本地文件。
- 审计只记录域、动作、结果和安全原因代码；不记录 CSV 正文、联系方式、订单原值、备注或解密内容。
- 受保护字段只在 Node 服务端解密，进入事实表时仍以密文保存；浏览器和小程序不接触密钥。
