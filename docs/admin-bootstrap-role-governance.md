# 首次系统管理员引导、双人角色治理与脱敏审计

## 当前状态

本阶段仅提供离线契约与未执行的 009 前向迁移。没有真实后台路由、没有预置引导记录、没有管理员身份或角色变化，也没有连接 CloudBase。匿名 staging 与 demo 继续禁止真实治理能力。

## 一次性首次引导

首次系统管理员不能从登录页自注册，也不能由前端声明角色。未来必须由受控管理流程预先生成一条短期授权，且只保存：内部用户 ID、外部 subject 的服务端 HMAC、一次性票据的哈希、到期时间和不含敏感正文的控制编号。

引导 RPC 同时满足以下条件才会在一个事务中创建外部身份绑定和首个 `system_admin` 角色：

- 服务端已验证外部身份，客户端拿不到 subject 哈希密钥；
- subject 哈希和票据哈希精确匹配一条未使用、未过期授权；
- 系统当前不存在任何有效系统管理员；
- subject 尚未绑定；
- 授权使用后立即标为 used，并替换票据哈希，不能重放。

009 默认不插入任何引导授权。未来预置动作必须走数据库管理身份与双人线下核对，不通过运行时业务 API，也不能把 subject、票据、API Key 或服务端密钥贴到聊天中。

## 双人角色授予与撤销

首次引导完成后，`system_admin`、`operations`、`reviewer`、`auditor` 的授予或撤销都分两步：

1. 一位已验证且近期重新认证的系统管理员创建幂等请求；申请人不能是目标人。
2. 第二位已验证且近期重新认证的系统管理员批准；批准人不能是申请人或目标人。

授予不会覆盖已有有效角色；撤销要求角色当前有效。撤销与角色更新在同一事务完成，并立即撤销目标人的所有活跃后台会话、拒绝其所有未使用高风险操作授权。下一次请求无法继续使用旧角色或旧令牌。006/007 的业务职责分离仍独立生效。

## 脱敏审计查询

只有具备 `audit.read` 的有效服务端会话可以调用固定审计 RPC。每次最多 100 条，不提供导出能力。结果只包含：时间、不可逆的内部参与者/对象引用、动作、对象类型，以及严格白名单中的状态、原因码、角色码、变更动作和业务域。

查询不返回管理员 subject、会话哈希、票据、联系方式、CRM/付款正文、附件、对象键、上游响应或任意 `safe_change_summary` 原文。数据库或网关异常统一 503，不能回退内存审计。

## 未来人工执行顺序（现在不要执行）

只有 008 已人工执行并终检全部为 true、正式外部身份方案已确定、备份与回滚窗口就绪后，才按以下顺序操作：

1. `server/db/migrations/009_admin_governance.sql`
2. `server/db/cloudbase-pg-console/640_record_admin_governance_version.sql`
3. `server/db/cloudbase-pg-console/690_verify_admin_governance_readonly.sql`，所有结果必须为 true，且 `no_bootstrap_authorization_seeded` 必须为 true

009 使用显式 `BEGIN` / `COMMIT`。CloudBase ExecutePGSql 对逗号连接的多函数授权兼容性不稳定，因此最新版不再在 `DO` 中做条件授权，而是依赖已验证的 008 角色前置条件，为每个函数分别执行一条静态 `REVOKE` / `GRANT`。若旧版 009 在最后授权块报错，先不要执行 640；直接用最新版 009 整段重试。即使控制台曾逐句提交了前面的建表/函数，`IF NOT EXISTS` 与 `CREATE OR REPLACE` 也允许安全重跑，最新版重试本身会作为一个事务完成或整体回滚。

之后仍不能立刻开放后台。还需要独立完成：首次引导授权的安全生成/销毁流程、真实外部身份验证、受保护路由接线、应急恢复演练和至少两位系统管理员的职责安排。
