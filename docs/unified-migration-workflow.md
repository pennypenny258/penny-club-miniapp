# 统一迁移工作流：资料、CRM、付款证据与自愿公开名册

## 用户从哪里开始

打开运营后台，进入 **资料与导入 → 迁移总览（首选）**。总览把四类导入放在同一套阶段中，但不会合并四个事实域：

1. 准备模板或文件；
2. 上传 / 建批次；
3. 预检表头、字段映射、格式和安全规则；
4. 修正冲突或失败项，再次运行同一校验；
5. 人工审核；
6. 资料发布，或 CRM / 付款 / 名册分别物化与审批。

页面显示每条泳道的批次数、条目数、异常、待审核、已完成数量和下一步。当前全部是匿名内存演示，重启后不保留，不能当作正式迁移成果。

## 四条独立泳道

### 本地资料

入口：**从电脑导入资料**。可选择或拖拽白名单文件，设置分类、标签、来源说明和下载开关。上传后始终进入待审核。

- 发布前确认分类、来源/版权和文件安全；
- 发布资料默认可以进入受控阅读入口；“允许会员下载”只控制下载按钮；
- PDF / Office / 视频的正式在线预览或转码尚未接入，后台继续显示“在线预览能力待配置”；
- 私有附件路径、对象键、原始来源链接不进入会员响应。

### 内部 CRM

入口：**内部 CRM 导入**，模板 `internal-crm-verification.csv`。字段包括内部会员引用、受保护匹配令牌、CRM 核验状态、会籍窗口、群状态、受保护证据备注和迁移状态。

CRM 只写私有核验域。匹配冲突、未知群状态、未核验状态或不完整会籍窗口必须人工处理。即使 CRM 通过，也仍需独立付款证据和最终会籍判定。

### 付款证据

入口：**付款证据导入**，模板 `wechat-shop-order-evidence.csv`。先把来源订单状态映射为标准状态，并配置本批次允许的产品规则；手机号、金额、付款时间和产品名只在受保护层参与匹配/复核。

订单只形成付款证据候选。退款、净收款、产品规则或匹配有疑问时必须人工复核；单笔订单绝不直接激活会籍，也不产生公开名册。

### 自愿公开名册

入口：**自愿名册导入**，模板 `voluntary-directory-import.csv`。只有 `public_display_consent=yes`、`contact_mode=request_only` 且预检通过的行才能提交独立人工审核。

CRM、付款证据和最终会籍均不能自动生成名册。联系方式不导入公开资料，固定采用平台内申请对接；撤回同意或未明确同意的行直接排除。

## 异常修正与重试

预检会创建临时批次和逐行结果。进入 **异常修正**，只修改该导入类型允许的字段，保存后服务端重新运行同一个校验器并刷新批次统计。公式注入、未知字段、危险表头和越权映射不能通过“改列名”绕过。

异常不会自动跳过；排除项保留原因；待审核项不会自动发布或物化。正式持久化接入后，重试还必须带幂等键并保留批次审计。

## 可逆演练与回滚边界

“开始匿名演练”只在当前浏览器会话保存一个演练标记，不上传文件、不写批次或业务事实；“撤销本次演练”只移除该标记。这用于熟悉步骤，不会伪装成数据库回滚。

当前 CSV 预检批次和本地上传审核状态均为内存数据，重启可清空演示状态。未来正式迁移的回滚必须沿用 006/007 的逐行状态、补偿和不可变审计，不能用删除事实或覆盖审计代替。

## 现在可以做与不能做

现在可以：下载空模板、使用模板内匿名样例/空行演练、查看字段映射、制造匿名冲突并修正、熟悉人工审核顺序。

现在不能：导入真实会员、订单、CRM、名册或私有资料；把演示批次当作持久结果；执行 CloudBase SQL；配置真实 API Key、密码、AppSecret 或连接串。
