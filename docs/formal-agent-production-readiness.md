# 正式 Agent MVP 持久化准备

当前状态：**仅离线合约，未部署 RPC、未启用正式路由、未连接 CloudBase，也不会回退到内存假装持久化。**

## 固定流程

1. 成员通过 004 会籍门禁后，提交“我是谁、为什么找、找哪类人 / 机会”。记录只进入 `pending_review`。
2. 运营通过 008 正式后台授权人工处理：要求补充、拒绝、归档，或选择 `full_public`、`redacted_public`、`private_match`。
3. `full_public` 也只返回运营确认的公开投影；`redacted_public` 只返回安全标题、摘要和标签；`private_match` 没有公开投影。
4. 定向候选必须在人、机构、角色、事项四维中至少明确三项。同一需求与候选在 14 天内不得重复提醒，且始终由运营点击发送。
5. 对接申请必须包含“我是谁、为什么联系、希望讨论什么”。需求方同意后只形成 `operator_relay_pending`，联系方式仍由运营代转，API 不返回联系人。

所有路径均固定：`automaticPublish=false`、`automaticPush=false`、`contactDisclosed=false`。

## 未来 CloudBase RPC 能力

服务端适配器只允许以下固定操作，不接受表名、SQL、任意对象键或客户端角色：

- 已发布安全机会列表
- 需求进入人工审核
- 申请进入人工审核
- 记录需求人工终审
- 保存 3-of-4 定向候选与 14 天去重结果
- 记录 Agent 人工筛选
- 记录需求方决定
- 记录运营代转完成或取消

正式启用前必须由只读验收材料证明：仅 `service_role` 可执行、客户端角色全部拒绝、私有表强制 RLS、写操作幂等、状态机不可跳步、公开投影字段白名单、3-of-4 与 14 天去重由服务端执行、联系人只能运营代转、响应不含 CRM 或联系人原始字段。

仓库当前没有声称这些 RPC 已存在。`CLOUDBASE_AGENT_RPC_ENABLED`、能力版本或 manifest 摘要一旦被提前配置，服务会拒绝启动，而不是启用半成品。
