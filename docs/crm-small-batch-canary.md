# CRM 小批次 Canary（当前仅准备）

CRM 的首批真实数据不应从 1,000 多行历史表直接写入生产库。

上线时由运营人员从已核对的原始表中**人工挑选最多 50 名**已知会员，另存为一个独立 `.xlsx` 或 `.csv` 小表。系统不会从大表自动挑选人员，避免把重复昵称、到期待确认或群状态未知的人误带入首批。

小批次未来的顺序是：私有上传 → 脱敏预检 → 私有暂存 → 逐行匹配/补全/大群确认 → 独立复核 → 明确物化请求。付款、OCR 和价格档位都只提供 CRM 线索；它们不会单独开通会籍、发送通知或改动公开名册。

当前实现只生成安全的 canary 计划：不上传文件、不写 CloudBase、不保存原始值、不创建会员事实、不改变会籍。它仍等待 008 基线上的正式后台会话、受控导入 RPC、服务端密钥和匿名 canary 验收；不要现在尝试真实导入。
